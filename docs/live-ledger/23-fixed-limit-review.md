# 固定价格执行：ETF直接挂单、股票等待价格笼子

日期：2026-09-04。状态：本地修正，未部署；以本页替代上一轮未发布的“实时对手价自适应限价”方案。

## 决策与不变项

用户确认：策略决定期望价格，执行层只负责该价格何时可以申报及委托后的处理。不得因为交易所规则改用卖一/买一或笼子边界定价。

- GoodETF调仓买入仍为开盘后策略取得的 `last_price × 1.002`。
- 止盈仍为首次触发时参考价 `× 0.998`，不是全天固定用开盘价止盈。
- 调仓清仓/减仓和止损仍是原有市价IOC及当日补剩余量；先卖后买不变。
- 原报价精度、涨跌停处理、资金/归属校验仍保留。
- 选股池、过滤顺序、折价公式、排序、权重、风控阈值、JQ撮合和通知归属不变。
- 删除未部署的 `AdaptiveLimitExecution`、盘口重定价和额外执行协议升级；复用 `LimitExecution(2000)`，执行schema仍为v2，兼容v1。helper API仍为本次待发布的v18。

## 现在怎样执行

1. 策略提交目标权重和参考价；服务器按策略归属资金及该参考价计算目标数量，并持久化参考价。
2. `KEEP_ORIGINAL`下，等待、部分成交后的补单和笼子废单重试都使用初次参考价与相同偏移，不用后续tick的last_price重新定价。
3. ETF：直接提交原定限价，不再等待卖一回到买价以下/买一回到卖价以上；无成交时保持原委托排队。股票动态笼子不适用于ETF。
4. 股票：根据最新行情及板块计算可申报范围。原定价格在笼子内则原价申报，笼子外则等待下一笔行情，不把订单价格钳制到笼子边界。
5. 已报委托保持排队，部分成交只入账已成交量；上一笔终态后才按追单选项处理剩余量，防止重复活动委托。
6. 股票限价明确因笼子废单：保存拒单原因，等待更新tick，再检查原价是否可申报。重复目标请求也不能绕过这个检查。
7. 资金、权限、数量、未知原因等非笼子拒单停止自动重试并记录原因。通信结果未知仍走原有幂等/对账，不能当成确定拒单重发。
8. `FollowUpPolicy.NONE`不补终态剩余量；GoodETF的`UNTIL_FILLED_TODAY`只在当日处理。有效限价单不会因为价格变化而自动撤单提价；午夜关闭旧日目标。
9. 其他策略仍可以显式选择`ConditionalLimitExecution`或`RECOMPUTE`，其主动等待/重新定价语义不变；GoodETF不使用它们。

例如：原定买价10.02元，股票当前笼子上界9.89元，则等待；上界涨至10.09元后，仍报10.02元。ETF原定买价1.002元、卖一1.050元，则直接挂1.002元等成交，不报1.050元。

## 保留的T+0及行情工作

- 直连QMT优先使用`security_overrides.json`中代码级`tplus`，否则查询`T+0基金`板块；明确识别的新买入成交当日可卖，其余/识别失败按T+1。成功板块按日缓存，空结果或失败间隔60秒可重试，不使用基金类别默认T+0推断真实可卖量。
- 不回溯修改已经记账批次的可卖日，不借用手工持仓。最终可卖量仍受策略归属与券商实际可卖量共同约束。
- 原生tick缺少元数据时保留同一天已查询信息，不跨日沿用涨跌停数据。
- 不按ETF名称或上市日期猜测无限制。QMT没有返回有效上下限，不代表已经证明交易所无涨跌幅限制。
- 未修改独立回测引擎的通用基金默认配置。
