## 实现与复审

### 切片1：发单时段

- `SQLiteStrategyAPI`使用服务器的上海时区当前时间，在新目标入口、回调恢复入口和每笔派发前检查时段。请求中的历史`as_of`不能绕过检查。
- 发单窗口为周一至周五09:30（含）至11:30（不含）、13:00（含）至15:00（不含）。此处没有增加节假日日历，不能宣称完整识别所有非交易日；仅约束StrategyLedger自动执行，不改变原生broker接口。
- 午休/盘后仍查询并入账迟到成交，但不推进未完成目标、不派发待发订单。午夜目标过期及撤单规则不变。
- 48项API测试通过并复审，包括伪造请求时间、收盘前后边界、周末、逐笔检查、待发队列及休市时迟到成交入账。

### 切片2：订单与成交关联

- 本地订单不再由`(交易日, broker_order_id)`单值字典覆盖。关联时先筛交易日、证券、方向（委托还匹配数量），再用精确client_tag区分候选。
- 成交可用柜台合同号`order_sysid`关联已识别的委托；已入账成交则使用数据库持久化的原本地订单关联，不因后来同ID拒单改变归属。
- 旧回报被误附新策略标记、但证券/方向明确属于唯一旧单时，仍能识别旧单。相同证券/方向/ID且无唯一标记或合同号时，明确报关联不唯一，不猜测。
- 保留成交数量、方向、价格、时间等不可变字段验证；即使没有对应券商委托行，显式返回的成交方向也不能被本地方向覆盖。
- 委托终态与活动单检查改用本地订单ID；旧卖单的FILLED不能再结束新的买单。历史资金与已入账成交不重写。

### 切片3：缓存与整链路回归

- SQLite v11只改变`broker_order_history`：同日同ID允许多条带`observation_no`的独立观察记录；已有行逐字段迁移为第0条，不修改旧迁移校验和。
- 历史持久化及当前查询合并均按证券、方向、委托数量、标记、合同号和委托时间区分身份；状态、成交数量和价格不是身份字段。信息不足且存在冲突时保留独立观察，不拼接两个委托。
- QMT等待诊断缓存附加到查询行前检查证券、方向及已有标记，避免把另一委托的备注和等待快照粘到旧回报上。
- 加入同日同ID、同证券同方向、缓存重开后合并与对账、重复回报不重复记账，以及已入账成交数量/方向/价格真实变化仍报错的复现测试。ZERO_FALLBACK、费用未知、策略契约与导出门禁继续回归。
