# GoodETF：完整 QMT 内置 Python 版

QMT 策略运行不需要 MiniQMT、xtquant、聚宽或 BulletTrade 服务器。原有聚宽版和服务器保持原样。
回测需预先准备历史数据；提供的导出工具可借助聚宽研究的数据权限，导出后回测离线读取文件，不连接聚宽。
本目录是独立新版本，不是把旧策略切换到 BigQMT HTTP 网关。

**状态：本地假接口测试通过，尚未在你的券商 QMT 中验证。默认关闭交易。**
首次仅建议接券商模拟账户；“导入/编译成功”不等于行情和下单能力已经验证。

## 一个文件直接复制到 QMT

**唯一需要编辑、复制的策略文件是本目录的 `good_etf.py`。**
不需要配置模块、不需要构建或导出，也不需要在 QMT 安装本仓库。
`tests/`、本文档、`PLAN.md` 和历史数据导出工具不是 QMT 策略运行依赖，不要一并粘贴到策略编辑器。

文件内部按“顶部配置 → 策略决策及 QMT 入口 → 数据/账本/执行辅助”分区。
选股函数只表达决策，下面的辅助代码负责数据和执行。回测/实时共用决策，但执行适配分离；原实时选股和订单规则未改变。

### 1. 修改脚本顶部配置

打开 `good_etf.py`，所有用户配置都在最前面的“用户配置”区域：

- `ACCOUNT_ID`：仅实时使用；可留空，采用 QMT 策略交易界面所选股票账户。回测不要求填写、不读取柜台账号。
- `ENABLE_TRADING=False`：仅实时观察。设为 `True` 后会向所选账户发真实委托；软件不会辨别它是否是模拟账号。回测不受该开关控制，始终使用平台虚拟撮合。
- `INITIAL_CAPITAL=10000`：仅实时分给此策略的资金。首次发单前检查证券账户可用现金是否足够；已有账本时不能改数字重置。回测初始资金用 QMT 面板的值。
- `STATE_DIR`：客户端机器上的私有持久目录。不要删除、放进公开仓库或使用旧服务器账本覆盖。
- `ETF_SECTOR`：核对 QMT 中的全市场 ETF 板块名及成员数量；不能填仅含自选标的的板块并认为与原策略相同。
- `NAV_FILE`：可选，PCF 净值覆盖不足或日期不明时填写，格式见下。
- `BACKTEST_DATA_FILE`：仅回测使用，填写历史 ETF 池、前日单位净值、当日涨停价 JSON 的绝对路径；实时不读取。与单日 `NAV_FILE` 格式不同。
- `TRACKED_INDEX_NAMES`：可选的跟踪指数名称补充；简称不明确的港股基金尤其需要补齐。
- `FEISHU_WEBHOOK`：可选。卡片标题含策略 ID，单标的卡片另含名称和代码；正文每字段一行。
- `SH_NATIVE_MARKET`：沪市是否用原生五档即成剩撤。券商模拟柜台若不支持，设 `False` 使用保护价限价单。
- 选股/风控：`MAX_HOLD_NUM`、`MIN_MONEY`、`MAX_MONEY`、`DEPLOY_RATIO`、`STOP_LOSS_RATIO`、`TAKE_PROFIT_RATIO`、`SKIP_SUSPENDED_LIMITUP`。
- 港股过滤：`HK_WORDS` 和 `HK_CODES`，保留原有默认值。
- 时间：`PREPARE_TIME`、`OPEN_TIME`、`RISK_CHECK_TIMES`、`SNAPSHOT_TIME`，使用中国时区 `HH:MM`。
- 委托：`BUY_PREMIUM`、`PROFIT_DISCOUNT`、`MARKET_PROTECTION`、`QUERY_SECONDS`、`RETRY_SECONDS`、`CASH_RESERVE`。每项单位和含义都在对应行注释中。

修改完，在完整 QMT 中新建一个 Python 策略，将 **`good_etf.py` 全文** 复制到编辑器保存。
不要只复制 `init`/`handlebar`，下方辅助代码也是此单文件的一部分。

源文件的实际编码和首行声明均为 **GBK**（`# encoding:gbk`），与本次用户 QMT 编辑器的保存方式匹配。
本地编辑器请按 GBK 打开，中文显示正常后再全选复制到 QMT；不要改回 UTF-8 声明。
若已经粘贴了上一版，QMT 报 `utf-8 codec can't decode byte`，在 QMT 内把第一行改成
`# encoding:gbk`，保存并重新运行即可先排除此错误，不用重填账户配置。
后续编辑时必须同时保持实际 GBK 字节和 GBK 声明；只改其中一个仍会乱码/报错。
客户端需要可用的 pandas 和内置 Python API。单文件通过 Python 3.6 语法检查，未使用 dataclasses。
决策结果采用 NamedTuple；账本字典仅用于 JSON 持久化，不泄漏给策略决策代码。

### 2. 准备行情和净值

在 QMT 数据管理中补充全市场 ETF 的前一交易日日线，并保持每日更新。
历史日线采用 `subscribe=False` 从本地读取；不自动向每个 ETF 发网络下载请求。
缺失/过期日线或净值会列出数量与代码样例；个别缺失从候选中排除，全部缺失则跳过交易，不清仓。

净值只接受：

1. `get_etf_info(code)` 的 `nav`，且 `tradingDay` 是今天、`preTradingDay` 是前一交易日；
2. 用户提供的前日单位净值文件，文件 `date` 必须匹配前一交易日：

```json
{
  "date": "20260910",
  "nav": {
    "510300.SH": 4.1234,
    "159001.SZ": 100.0123
  }
}
```

示例数字仅说明格式，不可作为真实数据。覆盖文件中缺少的代码仍尝试 PCF。
不以 IOPV、最新成交价或过期 NAV 替代原策略单位净值。

**数据差异是本次迁移最重要的验收项：**QMT 板块、简称、PCF 覆盖和聚宽基金库不同；不能承诺每天选股完全相同。
公式、过滤顺序和参数保持不变；相同输入的过滤、排序和精确权重由契约测试核对。
跟踪指数缺失时保留原策略的简称/代码过滤降级。未按 `513*` 一刀切剔除海外 ETF。
历史回测走下面的独立数据入口，不用“今天的 PCF/板块”伪造历史数据。

### 3. 在 QMT 中回测

**自动识别 `ContextInfo.do_back_test`，不用改模式、不用开启 `ENABLE_TRADING`。**

1. 在聚宽研究中新建 Python/Notebook，将 `export_backtest_data.py` 全文复制运行。顶部填回测起止日期和输出文件名。首次建议先导出一周，核对权限和缺失数量；已有同名文件不会覆盖，重导时换输出名。该工具只查数据，不交易、不需要写账号密码。
2. 下载生成的 JSON 到 QMT 所在机器，例如 `C:\qmt_good_etf_data\good_etf_backtest_data.json`，在策略顶部 `BACKTEST_DATA_FILE` 填写此绝对路径。
3. 在 QMT 数据管理中补充文件涉及 ETF 的 **1 分钟和日线**，包括回测起始日的前一交易日。日线用于前日成交额过滤，分钟线用于当时价格和停牌状态；不自动用缺失行情补造收益。
4. 更新 QMT 中的 `good_etf.py` 全文，选择 **1 分钟、不复权**。回测区间不能超出 JSON 覆盖的交易日。初始资金、手续费、滑点在 QMT 回测面板设置，然后点击 **回测**，无需在模型交易中启动。
5. 预期日志包含 `[回测]`、历史日期、盘前候选、开盘目标权重和“回测目标市值”；成交、持仓、手续费、净值和收益指标看 **QMT 回测结果面板**。提交目标不等于已经成交，资金不足/T+1/撮合限制仍由平台处理。

策略运行仍只有一个 PY；JSON 是数据，不是额外代码模块。也可从其他可靠数据源生成下述格式，无需长期保留聚宽运行环境。

#### 回测与实时的明确区别

- 共用 `prepare/select/risk_signal`：过滤顺序、严格流动性边界、折价公式、排序、权重和止盈止损阈值未改变。
- 使用历史 bar 时间，不使用电脑当前时间；回测区间外预热 bar 不交易。没有 09:20 bar 时，盘前准备在首次开盘 bar 使用前日数据补做。
- 开盘在配置时间至下一分钟内首次有完整行情时执行一次。默认 09:30～09:31；QMT 1 分钟线通常在 09:31 才有首根完整 bar，因此使用其已完成的收盘价，而不是假设知道 09:30 第一笔 tick。这会与 JQ/实时开盘结果存在差异。
- 仅使用 QMT 回测专用 `order_target_value(..., ContextInfo, 虚拟账号)`，默认 `LATEST` 撮合。目标金额统一基于调仓前同一份总资产，先提交减仓、再提交增仓；不等待柜台回报，不添加分钟追单。`BUY_PREMIUM/PROFIT_DISCOUNT/MARKET_PROTECTION/RETRY_SECONDS` 等实时执行配置不用于回测。
- 回测不创建/读取/修改实时 JSON 账本，不占账本锁，不调用 `passorder/cancel`，不发飞书、不连接服务器。实时模式依然由原有执行器负责订单回报、固定限价及续单。
- 不读取今日全推、PCF、合约涨停价或当前 ETF 板块。分钟请求截止历史当前时间，拒绝未来/过期价格。缺整日数据、关键报价或历史涨停价时明确中止，本次结果不完整，不能把平直曲线当作有效回测。个别单位净值缺失仍按原策略排除并报告，全体缺失报错。
- 分钟数据需要 `close` 和 `suspendFlag`（官方 Bar 字段）。如果券商版本不提供该字段，不默认“全部未停牌”；需确认该客户端的历史停牌数据支持。

历史文件数据结构（下列数字仅为格式示例，不能当真实数据使用）：

```json
{
  "schema": 1,
  "sessions": {
    "20260911": {
      "previous_date": "20260910",
      "securities": {
        "510300.SH": {"name": "示例名称", "index_name": "", "nav": 4.1234, "high_limit": 4.5}
      }
    }
  }
}
```

每个交易日包含前一交易日的完整 ETF 池（保留源顺序，含未入选标的，不得只导出当前持仓/当前存续基金）；
`nav` 对应 `previous_date` 的单位净值，不是累计净值或 IOPV；`high_limit` 对应当前交易日盘前已知涨停价。
`nav=null` 表示未知并按原策略排除；`high_limit=null` **仅用于数据源明确无涨停限制**，不能用来填补未知。
日期与数据源实际发布时间须自行核对。导出器按历史日期取池，但数据源的 `display_name` 不保证为当时名称；跨历史更名时可能影响关键词过滤，可用可靠历史名称修正文件。未虚构历史跟踪指数名称。

**当前验收边界：本地假接口回归通过，不等于已在东莞证券 QMT 跑通真实历史回测。**
用户尚未提供历史文件，也尚未在该客户端验证数据字段、虚拟账户接口和撮合结果。平台回测也不能验证实时行情延迟、价格保护、柜台回调或追单成交能力。

### 4. 在 QMT 中实时运行

在完整 QMT 的**策略交易/模型交易界面**选择已登录的模拟股票账户，添加此策略并运行；不要把编辑器内运行当成真实委托验证。
建议主图使用沪深股票/指数、分钟周期，客户端机器设为中国时区。
策略需要在 09:20 前启动；09:20 至 09:30 间重启会在 09:30 补准备数据。错过 09:30 不补做全天开盘决策，等下一个交易日。

每日：09:20 准备；09:30 决策；10:30 / 13:30 / 14:50 风控；14:55 快照。
定时器 1 秒，委托/成交查询默认 5 秒补漏；回调入账后下一个定时器推进。它们不是交易所 tick 频率，也不保证知道每次价格变化。
`handlebar` 不交易，避免 QMT 初始化遍历历史 bar 时误触 `quickTrade=2`。

先检查日志中的板块总量、候选数量、数据缺失和目标卡片，与旧版同日结果比较。
确认后在脚本顶部修改 `ENABLE_TRADING=True`、复制更新并重启 QMT 策略，最好在下一个开盘前启用。
观察模式不会伪造持仓/成交，也不会保存一组将来自动生效的观察目标。

### 停止后重启报 PermissionError / 账本锁获取失败

旧版在 `msvcrt.locking(..., LK_NBLCK, 1)` 报 `PermissionError: [Errno 13]`，
表示未能获取账本锁，不是该行在创建目录。可能是另一个同账户/策略实例仍运行，
也可能是旧版缺少停止清理，QMT 停止策略后仍保留 Python 对象和文件句柄。

- 本版使用 QMT 的 `stop(ContextInfo)` 释放锁；启动失败也立即清理，不依赖进程退出或垃圾回收。
- 停止保留全部账本，且不查询账户、不下单、不撤单；已在柜台的委托不因停止策略而取消。
- 更新前的实例没有停止清理代码：保存配置并停止该策略，确认其他策略可以暂停后，完整退出并重新打开 QMT 一次，再启动更新后的脚本。保持 `ENABLE_TRADING=False`。
- 不删除 JSON 或 `.lock` 文件，不改账户/策略 ID 绕过锁，也不把管理员权限当成解锁方式。确认编辑器和模型交易中没有重复运行此策略。
- 正常停止后日志应显示 `策略已停止 | 账本锁已释放`，随后可使用相同账本重新启动。

## 交易行为

| 场景 | 行为 |
| --- | --- |
| 买入 | 开盘选股的 `lastPrice × 1.002` 为固定上限，按 ETF 价位单位向下取整；不使用卖一追价。ETF 直接挂限价，无股票价格笼子等待 |
| 调仓减仓、清理非目标策略持仓 | 沪市：原生五档即成剩撤，参考价下方 1.5% 保护；深圳：保护价固定限价。先确认所需卖出完成及入账，再买入 |
| 止损 | 跌破本策略成交均价的 95% 后，按上述受保护退出方式下单；低于保护下限仍可能卖不完 |
| 止盈 | 超过本策略成交均价的 110% 后，触发时 lastPrice 下方 0.2% 固定限价 |
| 部分成交 | 成交量/价入账；原单仍有效则等原单，不叠单。收到部撤/已撤且对应成交已入账，才按剩余量继续提交 |
| 未知/废单 | 无柜台编号或异常返回不盲目重发；废单显示原因，停止该标的当天自动续单，先处理柜台问题 |
| 到期 | 只在当天连续交易时段发新单（14:57 后不新发）；午夜清除目标并请求撤销遗留委托。确认以柜台回报为准；停机时在重启补处理 |

深圳原生市价接口不保证接受同样的保护限价，因此这里**不宣称与原 xtquant 服务端市价行为完全等价**。
限价单不主动按固定间隔撤单，也不会随着价格远离而不断改变参考价。
最终价格还受 QMT 提供的涨跌停价及最小变动单位约束，不写死 ETF 涨跌幅。
遇到停牌、T+1 可卖不足、盘口无对手、保护价之外等情况，**不保证全部成交**。

## 账本、费用和迁移边界

- 用证券账号 + 策略 ID 对应一个私有 JSON 账本，真实成交编号去重；重启继续使用它。请保持单实例运行。
- 只管理此版本发单成交形成的持仓；旧 remote 和手动持仓不会自动接管。手动卖出造成归属数量不足时，会提示核对。
- 10000 计划买 3000、只成交 2000：未计费用的现金为 8000；无策略归属持仓不会卖手动持仓凑目标。
- 费用取实际成交 `m_dCommission`/旧拼写 `m_dComission`。缺失标为未知，不以聚宽费率补造；之后查询补齐费用会更新现金。没有分项时不虚构印花税等明细。
- 显示权益/净值扣除已知费用；未知费用尚未扣除，因此不是最终交割单精确净值。持仓成本为本策略成交均价，不混入其他手动持仓成本。
- `CASH_RESERVE` 是活动买单购买力缓冲，不是收费，不写成手续费。
- 不包含多策略资金分配中心、自动分红拆股入账、旧服务器账本转换、跨客户端统一台账。多策略共用账户需要自行预留不重复分配的资金。
- **切换前必须停用旧 remote 的自动交易并核对/撤销旧活动委托。**此代码没有替你操作服务器，也不会擅自卖掉旧仓；是否迁移旧仓需另行确认。
- 交易关闭只禁止新发单/撤单，不会把已在柜台挂出的委托自动撤掉。
